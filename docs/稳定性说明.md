# 稳定性更新

本版保留视频背景，不改布局、额度显示或两秒一次的网页轮询。以下真机结果来自 2026-10-20 的短期验证，不代表所有设备或全天运行结果。

## 修复内容

- 默认视频改为 800×480、12fps、H.264 Baseline、无 B 帧，保持原播放速度；原视频保留。
- 只加载当前可见页的视频，切页或浏览器隐藏时释放后台解码资源。真正播放后再撤掉图片兜底，解码失败则恢复图片。
- 时钟冒号离散闪烁；完成高亮随两秒轮询更新；等待提示仅在小区域做透明度呼吸，减少持续重绘。
- 状态请求最多一个在途，五秒超时。连续三次失败才显示离线，网络恢复后在原页签继续更新。
- ADB 检查失败视为“未知”，不据此重建正常代理；连续三次确认代理失效才修复。结束旧进程前核对身份，防止重启后的进程编号复用误伤其他进程。
- 显式打开页面复用 Via 当前页签；ADB 重连不发送浏览器刷新按键。
- 代理日志增加时间、设备启动编号和 Via 进程变化，帮助区分整机重启、浏览器退出和网络重连。日志只保存在本机，不要原样公开。

## 更新后怎么生效

在项目目录中更新代码后，重启已安装的 ADB 代理，并在当前页签重新加载页面：

```bash
launchctl kickstart -k gui/$(id -u)/com.gerry.lx04-adb-bridge
python3 scripts/adb-bridge.py --open
```

若未安装开机自启，按 [使用说明](使用说明.md) 启动服务和代理。Mac 局域网地址继续由用户在本机配置或自动识别，仓库不包含运行环境中的实际地址、账号或密钥。

## 已验证

- 10 项代理回归测试通过，包括短暂失联、持续失效、旧进程身份保护和同页打开：

  ```bash
  python3 -m unittest discover -s scripts -p test_adb_bridge.py -v
  ```

- LX04 两页视频正常播放、切换；连续两次显式打开仍为一个页签。
- 状态服务暂停 23 秒后恢复，原页签约五秒后恢复数据，浏览器进程及设备启动编号均未变化。
- 视频模式十秒采样中，Via CPU 从约单核 94% 降至约单核 50%。单核 100% 表示占满一个 CPU 核心，不是整机占用口径；不同任务和设备会波动。

## 待验证

长时间稳定性和部分 Wi-Fi 无法连接的原因仍待验证。现有证据不足以认定所有闪退或整机自动重启均由页面引起，也不足以宣称已完全消除。此次不禁用系统小爱服务、不改 Wi-Fi 配置、不刷机。

## 回退与诊断

- 如需恢复原视频编码，将 `display/index.html` 的 `SRC` 中 `meili-lite.mp4` / `canyon-lite.mp4` 改回 `meili.mp4` / `canyon.mp4`，再重新加载当前页签。
- `http://127.0.0.1:8477/?stable=1` 仅作静态背景诊断，正常入口 `/` 仍使用视频。
- 保留请求超时、同页打开和旧进程身份保护，避免恢复已确认的问题。
